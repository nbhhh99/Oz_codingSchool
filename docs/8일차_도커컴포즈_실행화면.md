# 8일차 docker-compose 실행화면

프로젝트 루트의 `docker-compose.yml` 로 `fastapi` + `mysql` 서비스를 정의하고,
`docker compose` 명령으로 이미지 빌드 및 컨테이너 실행을 확인한 결과입니다.

## 구성 요약

### fastapi 서비스
- `app/Dockerfile` 로 이미지 빌드 (`build.context: .`, `build.dockerfile: app/Dockerfile`)
- 로컬 프로젝트를 컨테이너 `/app` 경로로 bind-mount (`.:/app`) → 코드 수정 즉시 반영
- 실행 커맨드: `alembic upgrade head` 로 스키마 반영 후
  `uvicorn app.main:app --reload` 로 기동 (`--reload-dir app --reload-dir worker`)
- `WATCHFILES_FORCE_POLLING=true` 로 bind-mount 환경에서도 `--reload` 파일 감지 보장
- `DB_HOST=mysql` 로 override 하여 compose 네트워크의 `mysql` 서비스에 접속
- `mysql` 이 `service_healthy` 될 때까지 대기 (`depends_on.condition`)
- 업로드 파일은 `media_volume` 에 영속화

### mysql 서비스
- `mysql:8.0`, `utf8mb4` 문자셋
- `.env` 의 `DB_*` 값으로 DB/계정 생성 (`MYSQL_DATABASE`, `MYSQL_USER` 등)
- 데이터는 `mysql_volume` 에 영속화
- `mysqladmin ping` healthcheck

## 실행 명령

```bash
# 이미지 빌드 + 컨테이너 기동
docker compose up --build

# 백그라운드 실행
docker compose up --build -d

# 상태 확인 / 로그
docker compose ps
docker compose logs -f fastapi

# 종료 (볼륨까지 정리: docker compose down -v)
docker compose down
```
